Changelog — 1.0.x

Archived changelog for the 1.0.x series of @peektravel/app-utilities. For the current version see the main changelog.

1.0.1

Shared Money model; BookingAddonMoney deprecated additive

  • What: The money shape { amount, currency, formatted } is now exported as a single shared Money type. BookingAddon.total is typed as Money | null, and the previously-exported BookingAddonMoney is retained as a @deprecated alias of Money.
  • Why: the same money shape is now returned by more than one resource (booking add-ons and availability prices), so it lives in one place instead of a resource-specific type.
  • Caller action: none — BookingAddonMoney still resolves (to Money). Migrate references to Money at your convenience.

AvailabilityTime gains minimumTicketsRequired and price additive

  • What: Each AvailabilityTime returned by getAvailabilityService().getAvailabilityTimes(...) now carries minimumTicketsRequired (a number) and price (Money | null, the per-ticket price). minimumTicketsRequired is normalized: when Peek reports 0 (no minimum) it is surfaced as 1, so it is always the smallest bookable party size.
  • Why: callers choosing a slot need the minimum party size and per-ticket price alongside the remaining availability.
  • Caller action: none — additive.

1.0.0

PeekAccessService mode is now a required "v1" | "v2" field breaking

  • What: mode on PeekAccessServiceConfig was an optional "v2" flag (omitting it meant "v1"). It is now a required "v1" | "v2" field, and the constructor throws ("mode" is required …) when it is missing or invalid — so an untyped JS caller gets a loud error instead of silently running on v1. "v2" is the app-registry connection to use going forward and now requires the install webhook's apiUrl — the constructor throws if "v2" is selected without one (there is no silent default base URL). "v1" is the legacy gateway and is now @deprecated and will be removed. If you don't yet have a webhook apiUrl, build one by appending your app slug to the registry prefix and pass that as the apiUrl yourself — https://apps.peek.com/installations-api/<app-slug> (the trailing app-slug segment is required; the old app-registry.peeklabs.com sandbox host is gone).
  • Why: v2 (the per-install apiUrl from the install webhook) is the forward-looking connection, and we want every consumer to move to it. Making mode mandatory turns a silent default into a deliberate, visible choice at update time rather than a behaviour that can drift unnoticed.
  • Caller action: pass mode explicitly.
    • If you relied on the previous default, the fastest no-behaviour-change update is to add mode: "v1" (keep your existing appId + gatewayKey). Then plan the migration to v2.
    • For v2, pass mode: "v2" and the install's apiUrl (persisted from the install webhook; see docs/webhooks.md). createAccessServiceForInstall already sets mode: "v2" for you, so callers using the install factory need no change. CNG/ACME configs are unaffected (they have no mode).
