Changelog — 1.1.x

Archived changelog for the 1.1.x series of @peektravel/app-utilities. For the current version see the main changelog.

1.1.3

AssignableBooking.notes — operator notes on assignable bookings additive

  • What: AssignableBooking (returned by SeatmapService.assignableBookings) gains a notes: string field carrying the booking's operator-facing notes — an empty string when the booking has none.
  • Why: callers reconciling seat assignments need the same operator notes they see elsewhere, without a second booking lookup.
  • Caller action: none — purely additive. The field is not PII-gated, so it is populated regardless of fullCustomerAccess.

1.1.2

SeatmapZone.colorHex — zone display color additive

  • What: SeatmapZone gains a nullable colorHex: string | null field — the zone's display color as a hex string (e.g. "#ff0000"), or null when the gateway reports none. It is populated on both getSeatmapForProduct and getSeatMapAssignments results.
  • Why: callers rendering a seating map need the zone color to match Peek Pro.
  • Caller action: none — purely additive.

1.1.1

SeatmapService.deleteSeatAssignments — delete seat assignments additive

  • What: SeatmapService gains deleteSeatAssignments(assignmentIds: string[]): Promise<DeletedSeatAssignment[]> — deletes seat assignments by id and returns the now-deleted assignments (for reloading state). New exported model DeletedSeatAssignment and typed error SeatmapDeleteError.
  • Why: the write that clears seats, pairing with the assignment reads/writes.
  • Caller action: none — purely additive. Notes for adopters: every id must start with asa_ and at least one must be supplied (validated before any network call — throws Error); on success you get back the deleted assignments ({ assignmentId, blockId, blockName, ticketHashId }); a batch-level failure from the gateway throws SeatmapDeleteError (reason on .message), while transport/GraphQL errors throw as usual.

SeatmapService.assignTicketsToSeats — bulk seat assignment additive

  • What: SeatmapService gains assignTicketsToSeats(assignments: SeatmapBlockAssignment[]): Promise<AssignmentResponse> — assigns bookable tickets to seats in bulk (one batched mutation). New exported types SeatmapBlockAssignment, AssignmentResponse, SuccessfulAssignment, the AssignmentStatus union, and the ASSIGNMENT_STATUSES constant.
  • Why: callers need to commit seat assignments (the write that pairs with the assignableBookings / getSeatMapAssignments reads), in one round trip.
  • Caller action: none — purely additive. Notes for adopters: each SeatmapBlockAssignment must carry an assignableId starting with t_ and a blockId starting with csb_, and at least one must be supplied — all validated before any network call (throws Error). The result's status is SUCCESS (all assigned), FAILED (none), or PARTIAL (some). successfulAssignments are { assignableId, assignmentId } pairs (the created asa_… record); failedAssignments lists the failed assignableIds. Per-assignment failures (overbooking, invalid type, …) are reported in failedAssignments, not thrown; only transport/GraphQL-level errors throw.

SeatmapService.assignableBookings — bookings assignable to seats additive

  • What: SeatmapService gains assignableBookings(productId, rangeStart, rangeEnd): Promise<AssignableBooking[]> — the confirmed bookings on a product that overlap a datetime range, each with the tickets that can be assigned to seats. New exported types AssignableBooking, AssignableTicket, and CurrentSeatAssignment.
  • Why: seat assignment needs the list of bookings/tickets eligible for a map and time window, plus which seat (if any) each ticket already holds.
  • Caller action: none — purely additive. Notes for adopters: assignableId on a ticket is its hashid (the handle you assign by); currentlyAssignedTo is null when a ticket has no seat yet; rangeStart/rangeEnd take the same flexible datetimes as getSeatMapAssignments (seconds optional, timezone/ fractional stripped, both bounds on the same date) sent half-open [start,end); booking startsAt/endsAt are returned without fractional seconds; and guestName is customer PII, so it is null unless the access service was created with fullCustomerAccess.

SeatmapService.getSeatMapAssignments — seat occupancy over a range additive

  • What: SeatmapService gains getSeatMapAssignments(productId, rangeStart, rangeEnd): Promise<AssignedSeatmap[]> — every seating map on an activity with each seat enriched by its occupancy over a datetime range. New exported types: AssignedSeatmap, AssignedSeatmapSection, AssignedSeatmapGroup, and AssignedSeatmapBlock (each extends its base Seatmap* type; AssignedSeatmapBlock adds status: SeatmapBlockStatus and assignedTo: SeatmapAssignment[]), plus SeatmapAssignment, the SeatmapBlockStatus / SeatmapOccupantType unions, the SEATMAP_BLOCK_STATUSES / SEATMAP_OCCUPANT_TYPES constants, and two typed errors UnknownSeatmapBlockStatusError and UnknownSeatmapAssignmentParentError.
  • Why: callers need who/what occupies each seat (bookings/guests, staff, field locations, blocked seats) for a given map and time window — not just the static layout getSeatmapForProduct returns.
  • Caller action: none — purely additive; getSeatmapForProduct is unchanged and still returns the base Seatmap[] without status/assignedTo. When adopting the new call, note: it takes the product id and returns every map on that activity (like getSeatmapForProduct), empty when there are none; rangeStart/rangeEnd accept flexible datetimes (seconds optional, any timezone/fractional seconds stripped) normalized to naive YYYY-MM-DDTHH:MM:SS and queried half-open [start,end) — and the two bounds must fall on the same date (it throws otherwise); an occupant's guestName is customer PII, so for a GUEST it is null unless the access service was created with fullCustomerAccess (staff/ACCOUNT_USER names are not gated); and an unrecognized seat status or assignment parent throws the matching new error (.status / .typename carry the offending value).

New SeatmapService for reading product seating maps additive

  • What: PeekAccessService.getSeatmapService() returns a new SeatmapService with getSeatmapForProduct(productId): Promise<Seatmap[]> — every seating map configured on an activity (empty when the activity is missing or has none). The clean models Seatmap, SeatmapZone, SeatmapTicket, SeatmapSection, SeatmapGroup, SeatmapBlock, and the shared SeatmapDisplay geometry are now exported, along with the SeatmapDisplayType union, the SEATMAP_DISPLAY_TYPES constant, and a new typed error UnknownSeatmapDisplayTypeError.
  • Why: callers need the physical seat layout (zones/pricing tiers, sections, tables, and seats) a product sells against, exposed as clean models instead of raw GraphQL.
  • Caller action: none — purely additive. Note two behaviors when adopting it: a product can have multiple maps, so the result is an array; and a gateway display.type outside SEATMAP_DISPLAY_TYPES ("SHAPE" | "SECTION" | "LABEL") throws UnknownSeatmapDisplayTypeError (.type holds the offending value) — catch it if you need to tolerate a newly-added kind. Seating maps are structural layout, not customer data, so the call is unaffected by fullCustomerAccess.

1.1.0

parseInstallWebhook takes installId from the token sub fix

  • What: InstallWebhook.installId is now always the verified token sub. The body install_id no longer sets it. parseInstallWebhook now throws the new exported InstallWebhookError in two cases: the body has a non-empty install_id that is not equal to the token sub (reason: "install_id_mismatch"), or the token has no sub (reason: "missing_subject"). A body without install_id still parses, with installId set from sub. InstallWebhookError extends JsonWebTokenError from jsonwebtoken, so code that branches on JsonWebTokenError also catches it. Before, the body install_id was used first and the token sub only filled in when the body had none.
  • Why: the install id of the event is now the one the signed token states. Peek's own deliveries put the same id in both places, so they parse as before.
  • Caller action: keep one try/catch around parseInstallWebhook and respond 401 for every throw (also InstallWebhookError). If your tests mint tokens, give each token a sub equal to the body install_id, or leave install_id out of the body.
